# document-writing

文書を、設計と執筆の2段階に分けて書くための Agent Skill です。
README、手順書、PR の本文、報告書をエージェントに書かせる人に向けています。
いきなり本文を書かせると、話の流れが整わずに書き直しが増えます。このスキルを入れると、エージェントは先に読み手とテーマを決め、見出しの並びを作ってから本文を書きます。

このリポジトリの文書は、このスキルで書くか、このスキルの規則で添削しています。`LICENSE` とテーマファイルの YAML は対象外です。

## できること

- 設計（Phase 1）: 読み手とテーマを決め、テーマを Why・What・How に分解して見出しの並びを作る。結果は「設計シート」にまとめる
- 執筆（Phase 2）: 段落ごとに言いたいことを1文で決めてから本文を書き、添削と校正をする
- 既存の文書の添削: 元の文書は書き換えず、指摘と直し方の案を表で返す
- 事実の確認: 数値・仕様・実行結果を一次情報で確かめる。確かめられなかった事実には `※要確認` を付ける

文書の種類ごとに、問いと見出しの型を書いたテーマファイルを11個そろえています。

| テーマファイル | 文書 |
| :-- | :-- |
| `tutorial` | チュートリアル、入門ガイド |
| `how-to` | 手順書、環境構築手順、運用手順 |
| `reference` | API リファレンス、設定項目の一覧、外部仕様書 |
| `explanation` | 設計メモ、アーキテクチャや概念の解説 |
| `readme` | README、リポジトリ・ツールの紹介文 |
| `report` | 作業報告、調査報告、実装した機能の紹介記事 |
| `proposal` | 企画書、提案書、技術選定の提案 |
| `pull-request` | PR・MR の本文 |
| `issue-bug` | issue（バグ報告）、不具合票 |
| `issue-feature` | issue（機能要望・タスク）、作業依頼の課題票 |
| `decision` | ADR、技術選定や方針の決定の記録 |

コミットメッセージ、コード内のコメント、UI 文言、3行以内の連絡は対象外です。

## 動作環境

`SKILL.md` を読み込むエージェントで使います。作者は Claude Code と Codex CLI で使っています。

レビューの段階は、選択肢を示してたずねます。選択肢を示すツールがエージェントにあればそのツールを使い、なければ会話に選択肢を並べます。
言語固有の規則は、日本語（`locales/ja.md`）だけがあります。ほかの言語で書かせると、共通ルール（`rules/common.md`）だけが適用されます。

## インストール

[skills](https://www.skills.sh/) の CLI で入れるか、リポジトリを clone します。

skills の CLI で入れる場合は、スキルを使うプロジェクトのフォルダで次を実行します。入れる先のエージェントは、CLI が表示する選択肢から選びます。

```bash
npx skills add sumx21t-3310/document-writing
```

clone で入れる場合は、エージェントのスキル用フォルダを clone 先にします。

Claude Code の場合:

```bash
git clone https://github.com/sumx21t-3310/document-writing.git $HOME/.claude/skills/document-writing
```

Codex CLI の場合:

```bash
git clone https://github.com/sumx21t-3310/document-writing.git $HOME/.codex/skills/document-writing
```

## 使い方

文書を書く依頼をすると、スキルが読み込まれます。

```text
このリポジトリの README を書いて
```

エージェントは最初に、レビューをどの段階で受けるかをたずねます。

| 選択肢 | 動き |
| :-- | :-- |
| 対話 | 設計の手順ごとに結果を示し、確認を取りながら進める |
| プラン | 設計シートができた段階でレビューを受ける |
| 自動 | 設計を確認なしで進め、本文まで書き切る |

書き終えると、エージェントは次の4つを報告します。

- 保存したファイルのパス
- 設計シートにない記述の一覧
- 残った `※要確認` の一覧
- 実行しなかった項目と理由

既存の文書を見てもらうときは、「この文書を添削して」と頼みます。

## ファイル構成

| ファイル | 内容 |
| :-- | :-- |
| `SKILL.md` | スキルの本体。設計と執筆の手順、添削の手順、受け入れ条件 |
| `rules/common.md` | 出力言語にかかわらず適用する、構成・文と段落・語の選び方の規則 |
| `locales/ja.md` | 日本語の文体・語順・文の長さ・語彙・表記の規則 |
| `reference/themes/<name>.yaml` | 文書の種類ごとの問い、見出しの型、受け入れ条件 |
| `samples/` | テーマファイルごとのサンプル文書。一覧は [samples/README.md](samples/README.md) にある。スキルの動作には使わない |

言語を足すときは、`locales/<言語>.md` を追加します。文書の種類を足すときは、`reference/themes/` に YAML を追加し、`SKILL.md` の一覧に行を足します。
