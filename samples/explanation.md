# 所有権: Rust が値の持ち主を1つに決める理由

所有権は、Rust のプログラムがメモリを管理するための規則の集まりです。
この文書では、所有権の規則と、Rust がその規則を選んだ理由を説明します。事実の出典は、末尾の「出典」に並べた公式ドキュメントとコンパイラの出力です。

## 所有権とは

所有権の規則は、次の3つです。

- 値には、持ち主（owner）となる変数がある
- 持ち主は、同時に1つだけである
- 持ち主がスコープを出ると、値は破棄される

コンパイラは、この規則が守られているかをビルドのときに確かめます。規則に反したプログラムは、コンパイルできません。

## なぜ所有権を理解するのか

所有権を知らずに Rust を書くと、ほかの言語では通る書き方がコンパイルエラーになります。
次のコードは、文字列を関数に渡し、そのあとで同じ文字列を表示しています。

```rust
fn shout(text: String) -> String {
    text.to_uppercase()
}

fn main() {
    let name = String::from("ferris");
    let loud = shout(name);
    println!("{name} -> {loud}");
}
```

コンパイラは、8行目で `error[E0382]: borrow of moved value: name` を出します。
所有権の規則を知っていれば、このエラーを「持ち主が `shout` に移ったあとで、元の変数を使った」と読めます。直し方は [手順書](how-to.md) にあります。

## 所有権の仕組み

所有権の動きは、移動、破棄、借用の3つで説明できます。

値を別の変数に代入するか、関数に渡すと、持ち主が移ります。これを移動（move）と呼びます。
移動のあと、元の変数は無効になります。整数のように `Copy` を実装した型は、移動せずに複製されるので、元の変数も使えます。
上のコードでは、7行目で `name` の値が `shout` の引数 `text` に移りました。そのため、8行目の `name` は使えません。

持ち主がスコープを出ると、値は破棄され、メモリが解放されます。解放のコードを書く場所は、プログラムのどこにもありません。

持ち主を移さずに値を使わせる方法が、参照です。`&name` と書くと、`name` の値を指す参照ができます。参照を作ることを借用（borrowing）と呼びます。
参照には、次の規則があります。

- 書き換えられる参照が1つあるか、読むだけの参照がいくつかあるかの、どちらかである
- 参照は、指している値が有効な間だけ使える

## 別案と選ばなかった理由

公式ドキュメントは、メモリの管理方法として、ほかに2つを挙げています。

| 方法 | 動き |
| :-- | :-- |
| ガベージコレクション | 使われなくなったメモリを、プログラムの実行中に定期的に探す |
| 手動の管理 | メモリの確保と解放を、プログラマーがコードに書く |

公式ドキュメントは、この2つを選ばなかった理由を直接には書いていません。書いているのは、所有権について次の2点です。

- 所有権の機能は、実行中のプログラムを遅くしない
- 2つの変数が同じメモリを指したままスコープを出ると、同じメモリを2回解放する。2回の解放はメモリを壊し、セキュリティの弱点につながる。Rust は、代入のあとで元の変数を無効にして、2回の解放を防ぐ

ここから先は書き手の見方です。1点目は実行中に探す処理を持つガベージコレクションとの違いで、2点目は解放を人が書く手動の管理との違いだと読めます。

## 所有権の制約

所有権には、書く人が引き受ける制約があります。

- 値を2か所で使うときは、参照を渡すか、`clone` で複製するかを書き分ける。コンパイラは E0382 の中で両方を案内する
- 規則に慣れるまでに時間がかかる。公式ドキュメントも、多くのプログラマーにとって新しい考え方だと書いている
