# スキルは、1つずつ単独のリポジトリにする

- ステータス: accepted
- 日付: 2026-10-05

## 背景

2026-10-05 に、`document-writing` を GitHub に公開することになりました。
それまでは、自作のスキルをすべて、1つの親リポジトリのフォルダとして管理していました。親リポジトリは手元にだけあり、公開していませんでした。

公開する `document-writing` の README は、次の2つの入れ方を案内します。どちらも、リポジトリを1つ指定して入れる形です。

```bash
npx skills add sumx21t-3310/document-writing
```

```bash
git clone https://github.com/sumx21t-3310/document-writing.git $HOME/.claude/skills/document-writing
```

公開の時点で、`document-writing` は親リポジトリの `.gitignore` で外し、フォルダの中に別のリポジトリを作っていました。公開するスキルだけが別のリポジトリで、ほかのスキルは親リポジトリに入っている状態でした。

## 決定

スキルは、1つずつ単独のリポジトリにします。親リポジトリはなくし、フォルダはスキルの置き場として残します。

この決定が及ぶのは、スキルのフォルダです。置き場の直下にある、スキルを検査するスクリプトと、リンクを張るスクリプトをどのリポジトリに入れるかは、決めていません。

## 理由

決め手は、所有者の意向です。所有者が「親のリポジトリをなくす」と決めました。そう決めた理由は、記録に残っていません。

次の2点は、決定に合う事実です。

- `git clone` で入れる手順は、リポジトリのルートがスキルのフォルダであることを前提にしている。clone した先が、そのままスキルのフォルダになる
- スキルごとにリポジトリが分かれていれば、公開するスキルと公開しないスキルを、リポジトリの単位で分けられる

2点目が所有者の理由だったかどうかは、推測です。

## 検討した別案

| 案 | 内容 | 選ばなかった理由 |
| :-- | :-- | :-- |
| 親リポジトリごと公開する | 複数のスキルを1つのリポジトリで公開する。skills CLI は、`--skill <名前>` でスキルを選んで入れられる | 記録に残っていない。推測では、公開しないスキルが同じリポジトリに入るため |
| 親リポジトリを残し、公開するスキルだけを別のリポジトリにする | 決定の前の状態を続ける | 所有者が、親リポジトリをなくすと決めたため。スキルによって管理のしかたが2通りになる |

## 影響

得るものは、次の2つです。

- スキルごとに、公開するかどうかと、公開する時期を決められる
- 利用者は、リポジトリを1つ指定するだけで、スキルを1つ入れられる

失うものは、次の3つです。

- 親リポジトリの3コミット分の履歴。退避せずに捨てた。履歴にだけ残っていた、削除済みの2つのスキルの中身も失った
- スキルを検査するスクリプトと、リンクを張るスクリプトの版管理。どのリポジトリにも入っていない
- 複数のスキルにまたがる変更を、1つのコミットにまとめること
