# ファイルを読めないときは、1行のメッセージを出して終了コード 1 で終える

- ステータス: accepted
- 日付: 2026-10-05

## 背景

2026-10-05 に、存在しないファイルを渡すと panic する不具合が報告されました（[issue-bug.md](issue-bug.md)）。
`wordfreq` は、ファイルの読み込みに `unwrap` を使っています。読み込みに失敗すると、次のメッセージを出して終了コード 101 で終わります。

```text
thread 'main' (14880) panicked at src\main.rs:40:41:
called `Result::unwrap()` on an `Err` value: Os { code: 2, kind: NotFound, message: "指定されたファイルが見つかりません。" }
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

決めた時点で、読み込みをする箇所は `main` の1か所だけでした。標準入力から読む要望（[issue-feature.md](issue-feature.md)）が出ており、読み込みの箇所は2か所に増える見込みでした。

## 決定

ファイルを読めないときは、`wordfreq: cannot read <パス>: <OS のメッセージ>` を標準エラー出力に1行で出し、終了コード 1 で終えます。

この決定が及ぶのは、入力の読み込みの失敗だけです。引数の誤りは、いまと同じく `usage` を出して終了コード 2 で終えます。
メッセージを日本語にするかどうかは、決めていません。

## 理由

決め手は、利用者が見るメッセージの違いです。決定のとおりに書き換えた版を作り、存在しないファイルを渡すと、次の1行が出ました。

```text
wordfreq: cannot read nofile.txt: 指定されたファイルが見つかりません。 (os error 2)
```

この1行には、コマンドの名前、渡したパス、OS が返した理由が入っています。ソースコードの行番号と、Rust の型の名前は入っていません。

終了コードを 1 にしたのは、引数の誤りの 2 と区別するためです。スクリプトから呼ぶ人は、終了コードだけで「読めなかった」と「書式が違う」を分けられます。

## 検討した別案

| 案 | 存在しないファイルを渡したときの出力 | 終了コード | 選ばなかった理由 |
| :-- | :-- | :-- | :-- |
| `unwrap` のまま | 背景に載せた3行 | 101 | 不具合の報告のとおり、利用者が原因を読み取りにくい |
| `expect("cannot read file")` に変える | `cannot read file: Os { code: 2, kind: NotFound, message: "指定されたファイルが見つかりません。" }` を含む3行 | 101 | panic のままで、行番号と型の名前が残る。渡したパスが出ない |
| `main` が `Result` を返し、`?` で失敗を渡す | `Error: Os { code: 2, kind: NotFound, message: "指定されたファイルが見つかりません。" }` | 1 | 1行になるが、型の名前が残る。渡したパスが出ない |

3つの案の出力と終了コードは、それぞれの形に書き換えた版を実行して確かめました。

## 影響

得るものは、次の2つです。

- パスを打ち間違えた利用者が、1行のメッセージで原因を読み取れる
- 終了コード 101 がなくなり、スクリプトで扱う値が 0、1、2 の3つになる

失うものは、次の2つです。

- 読み込みの1行が、`match` を使った7行になる
- 読み込みの箇所が増えるたびに、同じ形のメッセージを書くことになる

読み込みの箇所が3か所以上になったら、この決定を見直します。メッセージを作る処理を1つの関数にまとめるか、`main` が `Result` を返す形に変えるかを、そのときに決めます。「3か所」は、同じ処理を3回書いたらまとめるという目安から置いた値で、計測にもとづく値ではありません。
