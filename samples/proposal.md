# 提案: wordfreq のテストと clippy を、CI で毎回流す

## 提案の要旨

`wordfreq` に、push のたびに `cargo test` と `cargo clippy` を流す CI を入れることの承認を求めます。
費用はかからず、作業は設定ファイル2つの追加です。

## 課題

いまは、テストと clippy を、変更した人が手で流しています。流し忘れた変更は、そのまま取り込まれます。
手元で clippy を流したところ、取り込み済みのコードから次の2件が見つかりました。

| 流したコマンド | 見つかったもの | 関係する文書 |
| :-- | :-- | :-- |
| `cargo clippy` | `rank` のライフタイムの注釈を省略できる、という警告が1件 | [pull-request.md](pull-request.md) |
| `cargo clippy -- -W clippy::unwrap_used` | 40行目の `unwrap` が panic しうる、という警告が1件 | [issue-bug.md](issue-bug.md) |

2件目は、利用者から報告された不具合の原因と同じ行です。clippy を毎回流していれば、報告を受ける前に、同じ行に気づけました。

## 目標と範囲

目標は、次の2つです。

- push と PR のたびに、`cargo test` と `cargo clippy -- -W clippy::unwrap_used` が自動で流れること
- どちらかが失敗または警告を出した変更は、CI の結果が失敗になること

次のことは、範囲に入れません。

- 実行ファイルの自動リリース
- Windows 以外の OS でのテスト
- 既存の2件の警告を直すこと。直す作業は、それぞれの文書で扱う

## 進め方

1. Rust のバージョンを固定する `rust-toolchain.toml` を足す
2. GitHub Actions のワークフローを1つ足す。中身は `cargo test` と `cargo clippy -- -W clippy::unwrap_used -D warnings` の2つである
3. 既存の2件の警告が直るまで、該当の行に `#[allow(...)]` を付ける。付けた行には、直す文書へのリンクをコメントで書く
4. わざと警告が出る変更を push し、CI が失敗することを確かめる

## スケジュールと体制

作業は1人で進めます。承認の翌日に手順1から3を終え、その次の日に手順4で確かめます。

## 費用

GitHub Actions は、標準のランナーを使う公開リポジトリでは無料です（[GitHub Actions の課金の説明](https://docs.github.com/en/billing/concepts/product-billing/github-actions)）。このリポジトリは公開されているので、費用は 0 円です。

実行にかかる時間は、手元では `cargo test` が 0.6 秒、`cargo clippy` が 0.3 秒でした。CI では Rust の準備の時間が加わります。CI での時間は、まだ計っていません。

## リスクと対策

| リスク | 対策 |
| :-- | :-- |
| Rust の新しい版で clippy の警告が増え、コードを変えていないのに CI が失敗する | `rust-toolchain.toml` でバージョンを 1.95.0 に固定する。上げるときは、警告の修正と同じ変更にまとめる |
| `unwrap_used` の警告が、テストのコードにも出る | テストのモジュールに `#[allow(clippy::unwrap_used)]` を付ける。いまのテストは `unwrap` を使っておらず、警告は出ていない |
| 警告を消すために `#[allow(...)]` が増える | 付けるときは、理由をコメントで書くことをレビューで確かめる |

## 別案との比較

| 案 | 選ばなかった理由 |
| :-- | :-- |
| いまのまま、手で流す | 流し忘れを防げない。課題の2件は、この運用のもとで取り込まれた |
| コミットの前に流す仕組み（Git の pre-commit フック）を各自が入れる | 入れるかどうかが人に任される。入れていない人の変更は、確かめられない |
